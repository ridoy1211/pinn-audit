# Development study: data-only regularization selection

Prepared after the selected-example clean/noisy diagnostics on 3 November 2026.
This is a specified development experiment, not a preregistered confirmation.
Its role is to assess a classical baseline before defining a fair PINN comparison.

## Question and population

For this exact, unit-square, two-mode heat benchmark, does five-fold observation
cross-validation provide useful recovery compared with unregularized fitting and
the fixed lambda=1e-6 used in the pilot? The answer may be negative. Validation
prediction error does not guarantee correct diffusivity or initial-field recovery.

Generate 20 new development datasets: N=10 with seeds 1000-1009, and N=50 with
seeds 2000-2009, using the existing generator. Coordinates are uniform on the unit
space-time square. Noise standard deviation remains 5% of each dataset's sampled
clean-signal standard deviation, matching the earlier pilot. Save that realized
sigma; this is not a fixed absolute noise level across datasets. The simulation
generator knows truth, while the tuning function receives only x, t, noisy y,
fold labels, and declared fitting settings. Datasets at different N are not nested.

## Fixed fitting and selection rules

- Six unknown initial sine amplitudes; alpha bounds [1e-5,1] for every method.
  These wide bounds retain the observed low-alpha failure region. They are a
  declared domain assumption, not a validated physical prior.
- Candidate lambdas: 0, 1e-8, 1e-6, 1e-4, 1e-2. Do not expand the set after
  inspecting recovery errors within this run.
- Five balanced folds, generated by a deterministic permutation with seed
  `30000 + data_seed`. Every observation is validated once. All candidates use
  identical folds. Fit on the other four folds, and compute squared prediction
  error only on the excluded observations.
- Select minimum pooled validation MSE; an exact numerical tie selects the
  smaller lambda. The regularization objective uses training-sample mean squared
  error, preserving its scale when training sample count changes.
- Refit all five candidates on all observations, independently of truth scoring.
  Report the selected full-data fit, plus lambda=0 and fixed lambda=1e-6. Archive
  all candidates and fold fits, regardless of outcome.
- Use 401 alpha-profile points and existing local refinement in every fit.
  There are 600 fits total: 20 datasets x 5 candidates x (5 folds + 1 full fit).
  This resolution is a declared computational choice, not proof of global search.

## Evaluation and retention

Select lambda before computing truth-based scores. Report coefficient relative
error, full-field relative L2 error, initial-condition relative L2 error, lower/upper
bound hits, candidate choices, and complete outcomes. Full-field and IC scoring
use the existing 401-point trapezoidal quadrature. Summarize medians, means, maxima,
and paired wins by N; do not treat folds as independent experimental replicates.
These descriptive results are not significance claims or a final confidence study.

Record validation MSE for every candidate/fold, all fitted amplitudes/profiles,
observation values, fold labels, environment, source/input hashes, and timestamps.
Report tuning fit time and total per-dataset elapsed time separately. This script
is not a fair timing benchmark: it refits all candidates to preserve diagnostics.
Any exception stops the run with partial evidence retained and status failed;
do not silently drop the dataset, regenerate it, or change its seed.

The development run may guide subsequent method/protocol choices, so it must not
later be relabeled held-out confirmation. Reserve a separate dataset set and neural
training seeds once the full comparison protocol is frozen. Bounds, model-family
advantage, loss/prior choices, neural tuning budgets, and independent field tests
remain unresolved for that comparison. Cross-validation at N=10 can be unstable.

## Commands

```cmd
python scripts/development_cv.py --out-dir results\data_only_tuning_development_v1
```

This must use a fresh output directory. A separate `--smoke` run uses seeds
987000/987001 and is for software verification only; it must not be pooled into
the 20-dataset study. The assistant verifies the smoke cases before handing over
the command and does not inspect the default study's outcomes beforehand.
